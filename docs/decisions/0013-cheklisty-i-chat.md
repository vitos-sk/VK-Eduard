# 0013. Чеклисты с чатом 1 на 1 и отправкой в WhatsApp

**Дата:** 2026-10-15
**Статус:** принято

## Контекст
Рабочим нужны списки справ («что взять на объект», «сдача объекта»), которые любой может создать и переслать коллеге: внутри приложения и через WhatsApp, куда бригада уже пишет.

## Решение
- **Чеклист — отдельный раздел** (вариант A из макетов): вход с главной и из «+». Нижняя панель из пяти пунктов не меняется.
- **Копия на получателя.** Отправка создаёт у коллеги свою копию со своими галочками; оригинал не меняется. Отправитель видит прогресс копии в карточке чата. Так не нужны общие списки и права «кто что может отмечать».
- **Чат 1 на 1 создаётся сам** при первой отправке. Только двое участников; **шеф чужие чаты не видит**. Групп и файлов нет.
- **Вход в чат — значок в шапке главной** с числом непрочитанных (вариант 1 из трёх), на компьютере — пункт боковой панели.
- **WhatsApp без API.** Кнопка открывает `wa.me/?text=…` с готовым текстом: список (читается и без приложения) и ссылка `/c/<токен>`. Токен — секрет в ссылке; открыть может только вошедший сотрудник той же фирмы, нажатие «Додати собі» создаёт копию и чат с автором.
- **Права и атомарность — в базе:** копии, чаты и карточки создают функции `security definer` (`send_checklist`, `accept_checklist`, `open_chat`), а не приложение с сервисным ключом.
- **Две записи — с сервера, после проверки доступа через RLS:** отметить пункт чужой копии (приславший отмечает в чате за коллегу) и удалить карточку из чата. Обычная политика этого не разрешает (пункты меняет владелец, текст сообщений не удаляется), а отдельная миграция на каждое такое действие превращала каждое улучшение в ручной шаг для владельца. Действие сначала читает запись обычным клиентом (RLS показывает её только владельцу копии и двум участникам чата), и лишь если запись видна, сервисным ключом меняется ровно эта запись и ровно одна колонка (`done_at`) или удаляется ровно эта карточка. Покрыто тестами `actions.test.ts`: без подтверждённого доступа сервисный ключ не вызывается.
- **Сообщения — опросом** раз в 4 с (пока вкладка видна), а не Realtime: меньше настройки и не ломается за прокси; Realtime можно добавить позже без изменения данных.
- **Возврат по ссылке после входа:** `proxy.ts` передаёт исходный адрес в `/welcome?next=…`, форма входа вернёт на него (через `safeNextPath`).
- **Уведомления:** push через уже существующие подписки; отдельные настройки (`notification_prefs`) для напоминания о звіте, сообщений, присланных чеклистов и «чеклист виконано».

## Последствия
- На iPhone ссылка из WhatsApp открывается в Safari, где нужен отдельный вход (у установленного приложения своя сессия). Список из текста сообщения читается в любом случае.
- Ответы из WhatsApp в приложение не возвращаются.
- Миграция `0021` обязательна для разделов «Чеклисти» и «Чати».
