# 0001. Supabase как база и Vercel как хостинг

**Дата:** 2026-09-07
**Статус:** принято (решение человека, зафиксировано)

## Контекст
Нужны база, авторизация и хранилище фото для приложения на Next.js. Команда — один-два
человека, отдельного администратора баз данных нет и не будет.

## Решение
Supabase (Postgres + Auth + Storage) и Vercel. Клиент — `@supabase/supabase-js`
плюс `@supabase/ssr` для App Router.

## Почему
1. Postgres — скучная проверенная база, а не эксперимент. Всё, что мы делаем, — это
   таблицы и джойны.
2. RLS переносит права доступа в базу. Баг в React не покажет чужие часы, потому что
   строки просто не придут.
3. Auth и Storage идут в комплекте. Отдельный сервис для файлов и отдельный для входа
   для команды такого размера — лишние две системы.

## Чем платим
Привязкой к платформе. RLS-политики и функции Supabase не переносятся в другую базу
дословно, потребуют переписывания. Storage-пути и подписанные ссылки — тоже.
Для нашего размера это правильный размен: меньше кода, который придётся чинить ночью.

## Что рассматривали ещё
- **Свой Postgres + свой бэкенд.** Полный контроль, но нужно писать и обслуживать
  авторизацию, загрузку файлов и деплой. Отпало по трудозатратам.
- **Firebase.** Нереляционная модель плохо ложится на табель, где всё считается
  агрегатами по периодам.
