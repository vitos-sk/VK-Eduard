# 0006. Защита маршрутов в proxy.ts, а не middleware.ts

**Дата:** 2026-09-07
**Статус:** принято

## Контекст
Supabase требует обновлять сессию на каждом запросе, иначе токен протухает и
пользователя выбрасывает. Официальные гайды Supabase описывают это через
`middleware.ts`. Но в Next.js 16 конвенция `middleware` **объявлена устаревшей и
переименована в `proxy`** — проверено в `node_modules/next/dist/docs`, не по памяти.

## Решение
Файл `proxy.ts` в корне, экспортирует функцию `proxy`. Внутри — обновление сессии
Supabase и редирект неавторизованных на welcome.

## Почему
1. `middleware.ts` в Next 16 работает, но помечен deprecated. Начинать новый код
   с устаревшей конвенции — значит запланировать себе миграцию.
2. Функциональность идентична, изменились только имена файла и экспорта.
3. Есть кодмод, если понадобится обратная миграция: `npx @next/codemod@canary middleware-to-proxy .`

## Чем платим
Любой скопированный из документации Supabase или из блога сниппет придётся
переименовывать. Это ловушка для того, кто придёт в проект позже, — поэтому
решение и записано.

## Что рассматривали ещё
- **Оставить `middleware.ts`.** Совпало бы с гайдами Supabase, но это осознанный
  выбор устаревшего API.
- **Проверять сессию в layout.** Не защищает Route Handlers и работает позже,
  чем нужно.
