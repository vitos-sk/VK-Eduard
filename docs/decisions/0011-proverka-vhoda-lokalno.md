# 0011. Проверка входа локально (`getClaims`)

**Дата:** 2026-10-05
**Статус:** принято; уточняет [0006](0006-proxy-vmesto-middleware.md)

## Контекст
`proxy.ts` на каждом запросе звал `auth.getUser()` — сетевой вызов в Supabase (~130 мс). Каждый переход между экранами начинался с лишнего ожидания, затем ещё запрос профиля.

## Решение
Проверять подпись токена локально через `auth.getClaims()` (публичные ключи проекта кэшируются). Если локально не подтвердилось — один раз спросить сервер (`getUser()`), чтобы сбой проверки не выбросил вошедшего. Идентификатор передаётся странице заголовком `x-user-id`.

## Последствия
- Нужны асимметричные ключи подписи в Supabase (Authentication → JWT Signing Keys); без них `getClaims` сам откатывается к серверной проверке — работает, но медленнее.
- Отозванный пользователь действует до истечения токена (до часа); `getProfile` дополнительно проверяет `is_active`.
- Это проверка маршрутов, а не авторизация: данные закрывает RLS.
