# «Звіти» — проработка экрана

Ядро продукта. Разобрано подробнее остальных, потому что от него зависит, будут ли
приложением пользоваться каждый день или забросят через неделю.

---

## 1. Что такое звіт

Звіт — это **запись о работе, у которой заполнили описание и фото**. Отдельной
сущности нет: и «Години», и «Звіти» показывают одни и те же строки `work_entries`,
просто с разным акцентом.

| | «Години» | «Звіти» |
|---|---|---|
| Вопрос экрана | *сколько* я работал | *что* я делал |
| Что крупно | часы, суммы, периоды | объект, описание, фото |
| Группировка | по периодам (день/неделя/месяц) | по датам, лентой |

Из этого следует главное свойство: **запись может существовать без описания**.
Рабочий нажал «Почати роботу» и «Завершити роботу» — часы зафиксированы. Описание
он допишет вечером в метро или не допишет вовсе.

---

## 2. Три состояния записи

Это не статусы в базе (поля `status` нет), а вычисляемые признаки. Тем не менее
в интерфейсе они должны читаться с одного взгляда.

| Состояние | Условие | Как выглядит на карточке |
|---|---|---|
| **Триває** | `ended_at is null` | пульсирующая зелёная точка, вместо часов — «з 07:30» |
| **Без опису** | `description = ''` и фото нет | приглушённая карточка, плашка «Без опису» и кнопка «Дописати» |
| **Готовий** | есть описание | обычная карточка с текстом и миниатюрой фото |

Отдельно — **статус синхронизации** (появляется на этапе офлайна): «не відправлено» /
«відправляється». Он живёт только на клиенте и рисуется маленькой иконкой облака
в углу карточки. Смешивать его с состоянием записи нельзя: одно про содержание,
другое про связь.

## 3. Структура экрана

```
┌─────────────────────────────────┐
│  Звіти                      [+] │   ScreenHeader
│                                 │
│  ── Мої ──   Команда            │   вторая вкладка только у boss
│                                 │
│  [ Пошук звіту...        ] [⚙]  │
│  ( Усі )( Без опису )( З фото ) │   SegmentedTabs
│                                 │
│  Цей тиждень      32:00 год     │   сводка по видимой выборке
│                                 │
│  Сьогодні                       │
│  ┌───────────────────────────┐  │
│  │ 3 червня, вт    10:00 год │  │
│  │ Об'єкт С – Покрівля  ┌───┐│  │
│  │ Мембрана, планки...  │фото││ │
│  │ 📷 3                 └───┘│  │
│  └───────────────────────────┘  │
│  ┌───────────────────────────┐  │
│  │ 2 червня, пн     8:00 год │  │
│  │ Об'єкт А – Покрівля       │  │
│  │ ⚠ Без опису    [Дописати] │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

### Что здесь важно

**Сводка над списком** («Цей тиждень — 32:00 год») считается по текущей выборке,
а не по всему. Меняешь фильтр — меняется цифра. Это превращает список в инструмент:
шеф может отфильтровать по объекту и сразу увидеть, сколько часов он съел.

**Фильтр «Без опису»** — не декоративный. Это рабочий инструмент: рабочий заходит,
видит три незаполненных дня и закрывает их за минуту. Шеф этим же фильтром видит,
кто не пишет отчёты.

**Группировка по датам** с заголовками «Сьогодні» / «Вчора» / «27 липня» — уже
реализована в текущем коде, сохраняем.

## 4. Вкладка «Команда» (только `boss`)

Экран «Команда та база даних» с макета переезжает сюда второй вкладкой — навигацию
не трогаем.

```
── Мої ──   Команда

[ Усі працівники ⌄ ] [ Червень ⌄ ]     два фильтра-дропдауна

┌──────────────────────────────────┐
│ (Е) Едуард          250:00 год   │
│     Цей тиждень: 50:00 год       │
├──────────────────────────────────┤
│ (В) Віталік         242:30 год   │
│     Цей тиждень: 48:30 год       │
└──────────────────────────────────┘

[ ⭳ Експорт звітів ]
```

Нажатие на человека → его лента записей за выбранный период. Дальше — обычная
детальная карточка.

Экспорт: CSV за период, колонки — дата, работник, объект, начало, конец, перерыв,
всего, отработано, сверхурочно, описание, число фото. UTF-8 **с BOM**, иначе Excel
покажет кракозябры вместо украинского текста.

## 5. Детальная страница `/reports/[id]`

Сейчас её нет вообще — карточки некликабельны. Она нужна, потому что дозаполнение
записи и просмотр фото в списке не помещаются.

- Шапка «‹ Звіт» + меню (правка, если в окне 7 дней)
- Дата и объект
- Полоса времени: Початок · Перерва · Кінець, под ней Відпрацьовано / Додатково
- Описание целиком
- Галерея фото: сетка, тап открывает во весь экран со свайпом
- Если описания нет — крупный блок «Додати опис» прямо на месте текста
- Кто и когда создал запись (важно шефу)

## 6. Форма записи `/reports/new`

Одна форма на два случая: создать запись с нуля и дописать существующую.

Порядок полей — по частоте изменения, самое изменчивое сверху:

1. **Дата** — по умолчанию сегодня
2. **Об'єкт** — по умолчанию тот же, что вчера. Это экономит нажатие в 90% случаев:
   люди работают на одном объекте неделями
3. **Час роботи** — Початок / Перерва / Кінець, под ними живой итог
   «Відпрацьовано 8:00 · Додатково 2:00»
4. **Опис** — textarea
5. **Фото** — до 6, с камеры или из галереи
6. Кнопка «Зберегти звіт»

### Предложения, которые заметно экономят время

Не обязательны, но каждое убирает реальное трение. Выбрать можно любые.

| Идея | Что даёт | Цена |
|---|---|---|
| **Подстановка последнего объекта** | минус одно нажатие каждый день | почти бесплатно |
| **Быстрые кнопки времени** («8 год», «10 год») ставят конец автоматически от начала | типовая смена в одно нажатие | дёшево |
| **Перерыв по умолчанию 1:00** для смен длиннее 6 часов | не надо думать | дёшево |
| **Повторить вчерашний звіт** — кнопка в пустом состоянии | тот же объект, то же время, описание чистое | дёшево |
| **Шаблоны описаний** — последние 5 своих описаний списком под полем | текст обычно повторяется: «монтаж мембрани» | средне |
| **Черновик не теряется** — форма сохраняется в IndexedDB на каждом изменении | закрыл приложение случайно — ничего не пропало | средне |
| **Фото сразу с камеры** (`capture="environment"`) | не надо лезть в галерею | дёшево |
| **Напоминание в 18:00**, если сегодня нет записи | главный способ добиться, чтобы приложением пользовались | требует push, iOS 16.4+ |

Моя рекомендация: первые четыре и «фото с камеры» — на этапе 4, черновик — вместе
с офлайном на этапе 5, напоминание — на этапе 7, если push вообще заведём.

## 7. Фото — где реально болит

Самая частая причина, по которой такие приложения бросают: «долго грузит» и «съедает
трафик».

| Проблема | Решение |
|---|---|
| Снимок с телефона 3–6 МБ | сжатие в браузере до ~1600px по длинной стороне, WebP q=0.8 → 200–400 КБ. Делаем **до** записи в очередь |
| Загрузка блокирует интерфейс | фото уходят фоном, карточка сразу видна с локальным превью |
| В ленте грузятся все фото сразу | в списке — только первое, размером 64px, `loading="lazy"` |
| Подписанные ссылки протухают | запрашиваем пачкой на экран, срок час, обновляем при возврате на экран |
| EXIF-поворот | canvas-нормализация при сжатии, иначе половина фото боком |

Ориентир: запись с тремя фото должна уходить меньше чем за 10 секунд на мобильном
интернете и весить меньше мегабайта.

## 8. Пустые состояния

Их часто забывают, а видят их чаще всего именно в первую неделю — когда решают,
пользоваться приложением или нет.

| Где | Что показываем |
|---|---|
| Ни одного звіту | иконка, «Ще немає звітів», кнопка «Створити перший звіт» |
| Фильтр ничего не нашёл | «Нічого не знайдено», кнопка «Скинути фільтри» |
| «Без опису» пуст | «Усі звіти заповнені 👍» — это награда, а не пустота |
| Вкладка «Команда» пуста | «Ще ніхто не додав звіти цього тижня» |
| Нет сети и кэш пуст | «Немає зв'язку. Звіти з'являться, коли буде інтернет» |

---

## 9. Чего в «Звітах» не будет

Названо явно, чтобы не расползлось:

- подтверждения и согласования шефом — решено, что их нет;
- комментариев и обсуждений под звітом;
- удаления — только правка в окне 7 дней;
- вложений, кроме фото (PDF, документы);
- звітів на несколько дней сразу.
