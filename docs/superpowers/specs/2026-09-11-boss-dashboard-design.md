# Дашборд шефа — окрема сторінка `/dashboard`

## Контекст

Зараз зведена статистика по компанії — це компактний блок `CompanyDashboard`
на «Головній» (тільки для `boss`): 3 stat-картки + топ-8 працівників за
поточний місяць, без вибору періоду.

Потрібна повноцінна окрема сторінка дашборда — за референсом (десктопний
дашборд з періодами Woche/Monat/Quartal/Jahr, 4 stat-картками, блоком
«Сьогодні», графіком динаміки годин, топ-об'єктами, годинами по
співробітниках і стрічкою активності) — але адаптована під наш стиль і
поточну модель даних, українською.

## Рішення

### Маршрут і доступ

`src/app/(app)/dashboard/page.tsx` — server component.

- `requireProfile()`; якщо `profile.role !== "boss"` → `redirect("/")`.
- Дані читаються напряму через `createClient()` в самому page.tsx (за
  зразком `more/page.tsx`), без окремого шару server actions — сторінка
  тільки читає, нічого не пише.

### Період

Query-параметр `?period=month|quarter|year`, за замовчуванням `month`.
**Без Woche** — за рішенням: тижневий розріз не потрібен.

Перемикач — звичайні `<Link>` з різним query (server-driven, без
клієнтського стану), так само як вибір місяця вже зроблено в «Годинах».

Межі періоду рахуються на сервері (`date-fns` вже є в залежностях —
перевірити перед додаванням нового хелпера).

### Дані

Один запит `work_entries` (join `profiles.full_name`, `sites.name`) за
обраний період, company-scoped (RLS сам обмежить `boss`-а його компанією).
З цього масиву на клієнті/сервері рахуються:

- **Годин загалом** — сума `total_minutes`.
- **Ø на робочий день** — сума годин / кількість днів, де хоч один запис.
- **Активні співробітники** — `count(profiles where is_active)`, окремий
  легкий запит.
- **Об'єкти в роботі** — кількість унікальних `site_id` серед записів
  періоду.
- **Сьогодні** — окремий міні-запит: записи з `work_date = сьогодні`,
  окремо відкриті зміни (`ended_at is null`) → бейджі з іменами.
- **Динаміка годин** — групування суми хвилин по днях (місяць/квартал) або
  по місяцях (рік).
- **Топ-об'єкти** / **Години по співробітниках** — групування суми хвилин
  по `site_id`/`author_id`, сортування за спаданням, без ліміту (весь
  список, скролиться в картці).

**Без порівняння з попереднім періодом** (без "+12%") — v1 показує лише
поточні цифри.

**Без стрічки активності** — сутності коментарів/звітів до об'єкта
(`site_reports`) ще немає в базі (тільки в планах), тож блок з референсу
не переносимо, поки цієї сутності не буде.

### Компоненти (`src/components/dashboard/`)

- `PeriodSwitcher` — три посилання Місяць/Квартал/Рік.
- `StatTile` — виноситься із `CompanyDashboard` як спільний компонент
  (зараз дубльований локально в ньому).
- `TodayCard` — «N з M активні» + бейджі відкритих змін.
- `HoursChart` — client-компонент на `recharts` (bar chart), нова
  залежність — у проєкті графічних бібліотек ще нема.
- `TopList` — спільний ranked-list з прогрес-баром для топ-об'єктів і
  топ-співробітників (та сама вёрстка, що вже є в `topWorkers` з
  `CompanyDashboard`).

Стиль — той самий, що і в `CompanyDashboard`/решти застосунку:
`bg-surface`, `border-border`, `rounded-[16px]`, без наслідування
темного скріну-референсу буквально (кольори/шрифти беремо свої).

### Навігація

- `DesktopSidebar`: пункт «Дашборд» одразу після `NAV_ITEMS`, рендериться
  тільки якщо `profile.role === "boss"`.
- Мобільний таб-бар (`NAV_ITEMS`, жорстко 2+FAB+2) не чіпаємо — на мобілці
  посилання карткою в `more/page.tsx`, також тільки для `boss`.

### Залежності

Додати `recharts` в `package.json`.

### i18n

Нові ключі в `src/lib/i18n/uk.ts`, окрема секція (наприклад
`dashboard: {...}`), не змішувати зі старою `admin.dashboard` (та
лишається для міні-блоку на «Головній»).
