# Адмінка (`/more/admin`) — дизайн

Дата: 2026-09-15

## Проблема и цель

Шефу (`boss`) нужен отдельный экран данных: посмотреть часы сотрудников за
выбранный месяц, выбрать «всі» или конкретных людей чекбоксами, выгрузить в
CSV/Excel/PDF и/или сразу отправить файл через WhatsApp. Плюс — возможность
выбрать, что открывается сразу после входа: обычное приложение или адмінка.

Роль «admin» — это существующая роль `boss`, отдельную роль не заводим.

## 1. Точка входа и доступ

- В `/more` (`src/app/(app)/more/page.tsx`) для `profile.role === "boss"`
  добавляется пункт «Адмінка» → `/more/admin`, по аналогии с существующим
  пунктом «Команда».
- Новый роут `src/app/(app)/more/admin/page.tsx`: server component,
  `requireProfile()` + редирект на `/more`, если `role !== "boss"` (как это
  уже сделано для `/more/team`).

## 2. UI страницы

Всё — переиспользование существующих паттернов (`EmptyState`, карточки
`border-border bg-surface-2`, `Thumb`/`initialsOf`, `SegmentedTabs`,
`PeriodNavigator`), новых визуальных примитивов не вводим.

- **KPI-ряд** (как на `/dashboard`): «Годин за період», «Активних
  співробітників», «Ø на співробітника» — по выбранной выборке и месяцу.
  На телефоне — горизонтальный скролл/2×2 grid, на ПК — ряд из 3 карточек.
- **Панель фильтров**: месяц-навигатор (◄ Вересень 2026 ►, тот же паттерн,
  что в `TeamTab`) + текстовый поиск по имени + кнопка «Усі / Зняти всі».
- **График**: горизонтальный `BarChart` (`recharts`, уже единственная
  графическая зависимость проекта, см. `HoursChart.tsx`) — один бар на
  работника из отфильтрованного списка, сортировка по убыванию часов,
  однотонный `var(--color-brand)` (одна серия — легенда и доп. палитра не
  нужны), hover-тултип с точным значением. Клик по бару переключает чекбокс
  этого работника в списке ниже.
- **Список работников**: карточка на человека (аватар-инициалы, имя, часы за
  месяц, мини-прогресс-бар относительно нормы) + чекбокс. На ПК — тот же
  набор данных в виде плотной таблицы-грида, сортируемой кликом по
  заголовку «Години».
- **Плавающая панель действий** — видна всегда (действует на «поточну
  вибірку»): показывает «Обрано: N» (или «Усі», если ничего не отмечено),
  кнопку «Експорт ▾» (CSV / Excel (.xlsx) / PDF-табель — переиспользуем
  список форматов `ExportMenu`) и кнопку «📲 WhatsApp».
- Пустое состояние (`EmptyState`) — если в компании нет работников; лоадер —
  простой skeleton в духе остальных клиентских экранов проекта (`TeamTab`
  и т. п.).

## 3. API: множественный выбор работников

`src/app/api/export/route.ts` — добавляем поддержку `workerIds` (через
запятую) рядом с существующим `workerId`:

```
?workerIds=id1,id2,id3
```

Если параметр присутствует — фильтр `rows.filter(...)` меняется с проверки
одного `workerId` на проверку членства в `Set<string>`, собранном из
`workerIds`. Существующий одиночный `workerId` (используется в кнопке
экспорта из карточки работника в «Команді») не трогаем — оба параметра
взаимоисключающие, но код может просто собирать `Set` из объединения обоих
при наличии. Формат/`kind`/RLS-логика не меняются.

## 4. Отправка через WhatsApp

Новый клиентский компонент `ShareWhatsAppButton` (соседствует с
`ExportMenu`, использует его список форматов):

1. По клику — `fetch` того же URL, что и обычный экспорт (`/api/export?...`),
   получаем `Blob` + имя файла из `Content-Disposition`.
2. Если `navigator.canShare?.({ files: [file] })` истинно (Android
   Chrome, iOS Safari 15+) — `navigator.share({ files: [file] })`: системное
   меню «Поділитися», пользователь сам выбирает WhatsApp.
3. Иначе (десктоп, не поддерживающие браузеры) — fallback: программно
   скачиваем файл (как обычная ссылка на экспорт) и открываем
   `https://wa.me/?text=...` с подсказкой «Файл завантажено, прикріпіть
   його вручну в чаті» — вручную прикрепить пользователю всё равно придётся,
   Web-версия WhatsApp не принимает файлы через URL.
4. Пока `fetch`/`share` выполняется — кнопка в состоянии `disabled` +
   спиннер (как в остальных async-кнопках проекта).

## 5. Дефолтный экран после входа

- Миграция `supabase/migrations/0011_profile_default_view.sql`: колонка
  `profiles.default_view text not null default 'app' check (default_view in
  ('app', 'admin'))`. Осмысленна только для `boss`, но колонка общая —
  отдельную таблицу заводить не нужно.
- Переключатель — сегмент-контрол прямо на `/more/admin` («Відкривати після
  входу: Застосунок / Адмінка»), сохраняется server action'ом
  (`updateDefaultView`, по аналогии с `updateFullName` в
  `modules/auth/actions.ts`), доступен только `boss`.
- `signIn` в `src/modules/auth/actions.ts`: после успешного
  `signInWithPassword` подтягиваем профиль (`getProfile`) и редиректим на
  `/more/admin`, если `role === "boss" && default_view === "admin"`, иначе
  как сейчас на `/`. Именно «после входа», а не на каждый заход на `/` —
  чтобы шеф мог свободно перейти на `/` вручную, не будучи туда отброшенным.

## Тестирование

- Ручная проверка на десктопе и телефоне (эмулятор + при возможности
  реальный Android с WhatsApp) — оба пути шеринга.
- `boss`/`worker` доступ к `/more/admin` — редирект для `worker`.
- Экспорт с `workerIds` — сверка содержимого файла с выбором в UI.
- Переключение `default_view` и повторный вход — проверка редиректа.
