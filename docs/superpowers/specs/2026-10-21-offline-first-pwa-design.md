# Офлайн-первое PWA: всё приложение открывается без интернета

**Статус (2026-10-21):** реализовано по плану `docs/superpowers/plans/2026-10-21-offline-first-pwa.md`; решения — ADR 0013. Воркер проверен вживую на стенде, интерфейс и реальные телефоны — по чек-листу `docs/PWA.md`, раздел 7.

**Цель:** после установки и одного захода онлайн приложение целиком живёт на телефоне. В авиарежиме открываются **все основные экраны** — с логотипом, шрифтами, кнопками, нижним меню и последними данными. Без сети не работает только то, что без сети невозможно: отправка отчёта, загрузка фото, правки, чат.

**Главный приоритет (слова автора):** чтобы без интернета приложение *визуально* открывалось красиво и понятно, а постоянные вещи (кнопки, логотипы, подписи) были на устройстве всегда.

## 1. Что уже есть (не ломаем)

Сервис-воркер `public/sw.js` (без библиотек), очередь «Додати час» в IndexedDB, кэш данных четырёх клиентских экранов (`lib/offline/cache.ts`), плашки «Немає зв'язку / Не відправлено», заглушка `offline.html`, очистка при выходе (`OfflineReset`). Подробно — `docs/PWA.md`, ADR 0003 и 0012.

## 2. Где сейчас дыры (найдено по коду)

1. **Заранее сохраняются только 3 страницы** из ~30: `/`, `/hours`, `/time/manual` (`WARM_PATHS` в `ServiceWorkerRegister.tsx`). «Об'єкти», «Звіти», чаты, чеклисты, «Ще» и всё внутри, зарплата, дашборд шефа без сети покажут заглушку «Немає зв'язку».
2. **Переходы внутри приложения воркер не видит.** Он ловит только `navigate`; нажатие на вкладку — это запрос данных Next (RSC), он мимо. Поэтому страница, которую человек видел, в кэш не попадает. Сеть пропала → Next (по моим знаниям) перезагружает страницу по адресу → копии нет → заглушка. *Поведение именно этой версии Next проверить на этапе 0.*
3. **Установка не скачивает приложение.** `install` кладёт только `offline.html`. Скрипты других экранов догружаются по ходу, поэтому «установленное» приложение без сети не полное.
4. **Версия воркера — ручная константа `v1`.** Файл не меняется между деплоями, телефон не знает об обновлении, а старые файлы в кэше статики копятся без границ.
5. **`offline.html` голая:** без логотипа, без подсказки, куда можно пойти.
6. **Нет честного состояния «показана сохранённая версия».** Плашка без даты; кнопки, которым нужна сеть (отправить отчёт, фото, правка), узнают об этом только после нажатия — ошибкой.
7. **Фото без сети — пустые квадраты.** Это подписанные ссылки Supabase (чужой домен, живут недолго). Нужна аккуратная заглушка (как сейчас ведут себя `Thumb`, `CardPhoto`, `Avatar` при ошибке загрузки — проверить на этапе 0).
8. **Нет `navigator.storage.persist()`:** телефон вправе выкинуть кэш при нехватке места.
9. **Страницы-детали** (`/objects/[id]`, `/reports/[id]`, `/chats/[id]`, `/checklists/[id]`) нигде не сохраняются заранее.

Причина 1–2 одна: все 32 страницы серверные, данные вшиты в HTML. Поэтому «офлайн» = сохранённые копии этих страниц + скрипты к ним.

## 3. Решение: четыре слоя

### Слой A — «Каркас» (всегда на устройстве)

- Воркер хранит всё, что нужно для отрисовки: скрипты и стили всех основных экранов, шрифты, иконки, улучшенную `offline.html`. Логотип и иконки — это inline-SVG внутри скриптов, отдельных файлов у них нет.
- **Как собираем список файлов** *(моё решение)*: без библиотеки, развитием уже работающего `warm`. Воркер открывает основные страницы, из их HTML берёт все `/_next/static/…`, из CSS — шрифты (`url(…)`), плюс единственный ленивый кусок — календарь (`lazy-calendar.tsx`). **Запасной вариант**, если замер покажет дыры: Serwist (`@serwist/turbopack`), он строит список прямо из сборки.
- **Версия воркера = номер сборки** *(моё решение)*: `/sw.js` отдаётся route handler'ом с подставленным `VERCEL_GIT_COMMIT_SHA`. Файл меняется при каждом деплое → телефон сам видит обновление. Заголовки `no-cache` сохраняем.
- **Чистка при обновлении:** старые файлы и страницы удаляем только **после** того, как новые сохранены. Иначе сохранённая страница старой версии остаётся без своих скриптов и не открывается.
- `navigator.storage.persist()` после входа.

### Слой B — «Все экраны открываются»

- **Прогрев после входа и раз в 6 часов** (как сейчас), но по полному списку: `/`, `/objects`, `/hours`, `/hours/salary`, `/reports`, `/chats`, `/checklists`, `/more` и его подстраницы (`profile`, `language`, `notifications`, `about`), `/time/manual`, `/reports/new`; для шефа ещё `/dashboard`, `/more/team`, `/more/company`. По одной, в паузах, не при включённой «экономии трафика» (`saveData`).
- **Страницы-детали («недавние»):** когда человек открыл объект, отчёт, чат или чеклист онлайн, через пару секунд простоя воркер сохраняет его копию. Хранится 30 последних (самые старые вытесняются). Цена: один лишний серверный рендер такой страницы, не чаще раза в 6 часов на страницу.
- **Переход по вкладке без сети** остаётся как сейчас: Next перезагружает страницу по адресу, воркер отдаёт копию. Это надёжно, но с перезагрузкой. Кэшировать сами RSC-ответы ради «без перезагрузки» **не берём**: формат меняется между версиями Next, а в этом Next уже есть ломающие изменения (см. `AGENTS.md`).
- Ожидание сети при наличии копии: 4 с → 2,5 с *(моё решение, подкрутим по ощущению)*.

### Слой C — «Честный интерфейс без сети»

- Плашка: «Немає зв'язку · показано збережене від 14:32». Время — последней успешной загрузки этого экрана (localStorage; без него просто без времени).
- **Умная `offline.html`:** логотип, понятный текст, кнопки на **реально сохранённые** разделы (страница сама читает Cache Storage), кнопка «Спробувати ще раз». Цвета — зеркало токенов, как сейчас (статичный файл вне React).
- **Действия, которым нужна сеть** (отправить отчёт, фото, правки, создание объекта, отправка в чате): кнопка неактивна, рядом короткое «Потрібен інтернет», **до** нажатия. Через общий `useOnline` и вариант в дизайн-системе (`Button`, `docs/DESIGN-SYSTEM.md`), без самописных `className`.
- **Фото:** единая заглушка (инициалы или иконка) вместо пустого квадрата, если картинка не загрузилась (`onError` в `Thumb`, `CardPhoto`, `Avatar`).
- Чат без сети: только чтение сохранённого, отправка выключена.
- Тексты на трёх языках (`uk`, `en`, `nl`).

### Слой D — позже, не в этой серии

Кэш миниатюр фото с лимитом по размеру; запуск «сначала сохранённое, потом обновить» (stale-while-revalidate); очередь для других действий (отчёт без фото, галочки чеклиста).

## 4. Цели, не-цели, провалы

- **Не-цели:** не переписываем страницы на клиентский рендер целиком; нет офлайн-отправки отчётов, фото и правок; нет фоновой отправки на iPhone (её нет в iOS); не прячем, что данные устарели.
- **Провал, даже если «технически работает»:** после выхода из аккаунта на телефоне остаются чужие данные; белый экран вместо заглушки; после деплоя телефон навсегда сидит на старой версии; кэш растёт без границ; прогрев заметно грузит сервер.

## 5. Риски

- **Размер каркаса:** замеряем на этапе 0. Рабочий бюджет — до ~5 МБ *(моя прикидка, не измерение)*.
- **Старые данные.** Копия может быть недельной давности (особенно опасно для зарплаты). Поэтому на плашке стоит время.
- **Приватность.** Копии страниц (зарплата, чаты) лежат на телефоне до выхода из аккаунта; стираются при выходе (уже есть, нужно проверить на новых страницах). См. вопрос 1.
- **iOS.** Установленное приложение не попадает под 7-дневную чистку Safari, но система может чистить при нехватке места → `persist()`.
- **Несовпадение версий** HTML и скриптов — закрыто правилом «чистим после прогрева».
- **Рабочее дерево:** сейчас не закоммичены правки по отчётам (`reports/*`, `notify.ts`, словари i18n). Мы тоже правим словари; начинать после их коммита или в отдельной ветке.

## 6. Этапы (каждый можно выкатить отдельно)

0. **Замер.** Боевая сборка локально (не трогая ваш dev-сервер на :3000), вход, прогрев, затем «сети нет» (остановить сервер или DevTools → Offline). Для каждого экрана записать: открывается или нет, что видно. Заодно размер каркаса и поведение фото. Итог — таблица-«до».
1. **Слой A:** воркер через route handler с номером сборки, прогрев с CSS и шрифтами, чистка после прогрева, `persist()`.
2. **Слой B:** полный список прогрева, «недавние» страницы с лимитом 30.
3. **Слой C:** плашка с временем, умная `offline.html`, неактивные кнопки, заглушки фото, три языка.
4. **Документы:** обновить `docs/PWA.md` (разделы 4, 6, 7), `docs/SCREENS.md`, добавить ADR 0013; пройти чек-лист на реальных iPhone и Android.

## 7. Как проверяем

- **Тесты (vitest):** чистая логика — какие пути греть, вытеснение «недавних», разбор файлов из HTML и CSS, номер версии — выносим в обычный модуль рядом с `lib/offline/`. Сам `sw.js` остаётся тонким.
- **Руками, по каждому экрану из слоя B:** открыть через нижнее меню и через перезапуск приложения в режиме «сети нет». Для каждого: видны логотип, шрифт, меню, данные, плашка с временем; кнопки отправки неактивны с подсказкой.
- **Выход из аккаунта:** после него сохранённых страниц и данных нет (проверить `caches.keys()` и IndexedDB).
- **Деплой:** после выкатки новой версии телефон подхватывает её, старый кэш чистится, офлайн по-прежнему работает.

## 8. Куда лезем

`public/sw.js` (→ `src/app/sw.js/route.ts` + исходник воркера), `next.config.ts` (заголовки, номер сборки), `ServiceWorkerRegister.tsx`, `AppShell.tsx`, `SyncBanner.tsx`, `lib/offline/*`, `public/offline.html`, `ui/button.tsx` (+ `docs/DESIGN-SYSTEM.md`), `Thumb.tsx`, `ui/card-photo.tsx`, `ui/avatar.tsx`, экраны с отправкой (`ReportForm`, правки, чат), словари `lib/i18n/{uk,en,nl}.ts`, документы.

## 9. Мои допущения и вопросы автору

**Мои решения** (можно оспорить): воркер без библиотеки, список файлов из прогрева; версия = номер сборки через route handler; «недавних» страниц 30; ожидание сети 2,5 с; RSC не кэшируем; фото без сети — заглушка, не кэш.

**Решения автора (2026-10-21):**
1. Все экраны открываются без сети, включая зарплату, чаты и дашборд шефа (ответ по умолчанию принят).
2. **Миниатюры кэшируем на телефоне** (фото объектов и аватары), место не ограничиваем жёстко (разумный потолок по числу файлов). **Фото отчётов (бакет `entry-photos`) не трогаем:** онлайн показываются как сейчас, в полном качестве, без сети — заглушка. Слой D «кэш миниатюр» поэтому переезжает в основную работу (слой C).
