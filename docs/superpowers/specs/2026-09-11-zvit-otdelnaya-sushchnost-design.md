# Звіт — отдельная сущность (не work_entries)

**Дата:** 2026-09-11
**Статус:** черновик, одобрен к реализации

## Контекст

`docs/REPORTS.md` и ADR-0002 описывают «Звіт» как витрину поверх `work_entries`:
одна и та же запись отвечает и «скільки» (Години), и «що» (Звіти), время обязательно.
На практике это блокирует создание звіта без ввода часів — форма `/reports/new`
требует Початок/Кінець, хотя по смыслу звіт должен быть просто дневником «що
робили сьогодні».

Решено разорвать связь: звіт становится отдельной сущностью без полей часу.
Риск расхождения цифр (названный в ADR-0002 как причина держать одну таблицу)
принимается сознательно — звіт больше не претендует быть табелем, это дневник.
«Години» и таймер не меняются.

## Модель данных

Миграция добавляет:

### `site_reports`

| Поле | Тип | Заметка |
|---|---|---|
| `id` | uuid pk | |
| `client_id` | uuid unique | идемпотентность офлайна, как у `work_entries` |
| `company_id` | uuid → companies | |
| `author_id` | uuid → profiles | |
| `site_id` | uuid → sites, null | null = поза об'єктом |
| `work_date` | date | |
| `description` | text, default `''` | необязательно — состояние «Без опису» сохраняется |
| `created_at` / `updated_at` | timestamptz | |

Правка — в окне 7 днів, как у `work_entries` (переиспользуем `editWindow.ts`).
Удаление не предусмотрено (тот же принцип, что в REPORTS.md §9).

### `report_photos`

Копия структуры `entry_photos`: `id`, `report_id` (fk on delete cascade), `storage_path`,
`width`/`height`/`size_bytes`, `sort_order`. Бакет `report-photos`, лимит 6 фото.

### `work_categories`

| Поле | Тип | Заметка |
|---|---|---|
| `id` | uuid pk | |
| `company_id` | uuid → companies | |
| `label` | text | «Покрівля» |
| `sort_order` | int | |
| `archived_at` | timestamptz, null | |

Стартовый набор на компанию (сидируется миграцией): Покрівля, Фасад, Демонтаж,
Монтаж мембрани, Заливка бетону, Електрика, Сантехніка, Оздоблення, Прибирання,
Інше. Экрана управления в v1 нет — таблица заведена так, чтобы `boss` мог
редактировать список позже без новой миграции.

### `report_categories`

Junction: `report_id` × `category_id`, мульти-select (0..N категорій на звіт,
необов'язково).

### RLS

Те же паттерны, что у `work_entries`/`entry_photos`: `company_id = current_company_id()`,
автор видит и правит свои записи в окне правки, `boss` видит все записи компанії.

### Бэкфилл существующих данных

Одноразовая миграция копирует все `work_entries`, где `description <> ''`
или есть фото, в `site_reports`/`report_photos` (без часів, без категорій —
категорії на старых записях остаются пустыми, дозаполняются вручную при желании).
Исходные `work_entries` не трогаем — «Години» продолжает их показывать как обычно.
Так существующая история звітів не пропадает при переключении экрана «Звіти»
на новый источник данных.

## Экраны

### `/reports/new` (`ReportForm.tsx`)

Убрать: блок «Час роботи» (Початок/Кінець, TimeInput×2, QUICK_DURATIONS_H,
переключатель перерви, вся связанная логика `minutesBetweenWrapped`/`isDurationValid`
в этой форме).

Добавить: ряд чипов «Вид робіт» (мульти-select из `work_categories` компании)
между «Дата» и «Опис».

`applyRepeatLast` копирует об'єкт и категорії, время не копирует (его больше нет).

Сабмит вызывает новый action (создание `site_reports`, не `createManualEntry`).

### `/reports/[id]` (`ReportDetail.tsx`)

Убрать полосу часу (Початок·Перерва·Кінець, Відпрацьовано/Додатково).
Добавить ряд чипів категорій (read-only вне правки, редактируемый в окне 7 днів
вместе з описом).

### `ReportsScreen.tsx` / `ReportsFeed.tsx`

Сводка над списком меняется с «Цей тиждень — 32:00 год» на «Цей тиждень — N звітів»
(+ доминирующая категорія, если є явный лидер: «переважно: Покрівля»).

Состояния карточки: «Без опису» / «Готовий» остаются, «Триває» убирается (это было
состояние часів, у звіта его больше нет).

Фільтри «Усі»/«Без опису»/«З фото» остаются без изменений.

### `TeamTab.tsx` (вкладка «Команда»)

Годинна сводка по сотруднику остаётся — она берёт данные из `work_entries`
(«Години»), не трогаем. Список звітів сотрудника в детальном виде читает
`site_reports`.

### Новая вкладка на `/objects/[id]`

«Звіти» рядом с существующими вкладками об'єкта: `ReportsFeed`, отфильтрованный
по `site_id`, плюс шапка-статистика — число звітів и распределение по категоріям
чипами со счётчиком («Покрівля · 5», «Демонтаж · 2»). Чисто read-only агрегация,
собственного стораджа не требует.

### `ExportMenu.tsx`

CSV-экспорт «Звіти»: колонки дата, працівник, об'єкт, категорії (через `;`),
опис, число фото. Часовые колонки (початок/кінець/перерва/усього/відпрацьовано/
сверхурочно) остаются только в экспорте «Години», который продолжает читать
`work_entries` без изменений.

## Что не трогаем

`work_entries`, таймер, «Години», ADR-0002 (остаётся в силе для табеля часів).
Подтверждения/коментарі/видалення звітів по-прежнему вне скоупа (REPORTS.md §9).

## Тестирование

- Создание звіта без единого поля часу — форма валидна с об'єктом+датою (опис
  и фото необов'язкові, как раньше).
- RLS: рабочий не видит чужие `site_reports`, `boss` видит всі.
- Бэкфилл: существующие звіти (описанные `work_entries`) видны в новой ленте
  после миграции, без дублирования при повторном запуске (идемпотентность по
  `client_id` или явная защита от повторного запуска бэкфилла).
- Экспорт CSV — новые колонки, UTF-8 с BOM (как раньше).
- Вкладка «Звіти» на об'єкте — правильная агрегация по категоріям для об'єкта
  с несколькими авторами.
