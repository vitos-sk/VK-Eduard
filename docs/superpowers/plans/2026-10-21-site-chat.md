# Чат объекта, меню чата, общий чеклист — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** у каждого объекта общий чат для всей фирмы, в любом чате меню «⋮» (очистить у себя, удалить у всех), в чат объекта можно положить общий чеклист.

**Architecture:** чат объекта — строка `chats` с `site_id` вместо пары людей; доступ решает одна функция `private.can_access_chat`, по ней переписаны политики. «Очистить» — отметка `chat_clears.cleared_at` на человека, её учитывает политика чтения сообщений (поэтому `my_chats`, непрочитанные и чужие чеклисты в карточках подчиняются ей сами). Приложение — Next.js (server actions + клиентские компоненты), база — Supabase Postgres.

**Tech Stack:** Next.js 16 (App Router), React 19, Supabase (RLS, RPC), Vitest, lucide-react, дизайн-система `src/components/ui/`.

**Spec:** `docs/superpowers/specs/2026-10-21-site-chat-design.md`

## Global Constraints

- Ответы и тексты интерфейса — украинский (`uk`), плюс `en` и `nl` с теми же ключами (словари `src/lib/i18n/{uk,en,nl}.ts`). Комментарии в коде — по-русски, как в соседнем коде.
- Только токены и компоненты дизайн-системы (`Button`, `Modal`, `Popover`, `Ticket`, `Avatar`…); никаких `#hex`, `bg-red-500`, самописных кнопок (CLAUDE.md).

- Миграции не правятся, а добавляются: `supabase/migrations/0023_site_chat.sql`. Применяет владелец вручную в SQL Editor проекта Supabase; мне эта база недоступна.
- **Не коммитить** без просьбы владельца: в дереве лежат чужие правки (офлайн-режим, отчёты). Файлы трогать только из списков задач.
- Типы базы `src/lib/supabase/types.gen.ts` дописываются вручную в формате генератора (автогенерация недоступна).
- Проверка кода: `npx vitest run`, `npx tsc --noEmit`, `npx eslint <тронутые файлы>` — всё зелёное.

## Review Focus

1. Сотрудник **другой фирмы** не читает и не пишет в чат объекта и не видит чеклисты в его карточках (SQL-сценарий, задача 1).
2. Очистка у A не прячет переписку у B; сообщение после очистки у A видно; чеклист из очищенной A карточки A больше не видит, а B отмечает его по-прежнему (задача 1).
3. Чат объекта не удаляет никто (удаление возвращает 0 строк → действие отдаёт ошибку); чат 1 на 1 удаляет любой из двух, у второго он пропадает (задачи 1 и 2).
4. Двое одновременно нажали «Відкрити чат» на новом объекте: чат один, `open_site_chat` оба раза отдаёт один id (задача 1).
5. Деактивированный сотрудник (`is_active = false`) не получает доступа к чату объекта; удаление объекта убирает его чат вместе с сообщениями (задача 1).
