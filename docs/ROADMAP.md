# План по этапам

Правило: **каждый этап заканчивается работающим приложением**, которое можно открыть
на телефоне и показать. Не «неделя на базу, неделя на бэкенд, неделя на фронт» — так
три недели нечего проверять.

Порядок неслучаен. Самый рискованный и ценный кусок — этап 3 — идёт третьим, а не
последним. Офлайн (этап 5) — только после того, как онлайн-путь доказал, что работает.

## Этап 3. Часы по-настоящему — ✅ сделано

Главный сценарий: от кнопки «Почати роботу» до строки в базе.

**Сделано:**
- `modules/time/calc.ts` — чистые функции расчёта, **27 тестов** в `calc.test.ts`:
  ночная смена 22:00→06:00, перерыв на границе полуночи, сверхурочные,
  открытая запись, `hhmmOf`/`dateKeyOf` (см. врезку про часовой пояс ниже)
- `modules/entries`: `queries.ts` (чтение — работает и с серверным, и с браузерным
  клиентом Supabase), `actions.ts` (Server Actions: `startShift`, `stopCurrentShift`,
  `startCurrentBreak`, `endCurrentBreak`, `createManualEntry`), `period.ts`
  (сводки дня и периода из плоского списка записей)
- `modules/sites/queries.ts` — активные объекты компании для формы записи
  (раньше форма ссылалась на моковые id объектов, которых нет в базе)
- Таймер на «Годинах» и «Головній» читает открытую запись из базы: перезагрузка
  страницы и смена устройства не сбрасывают счётчик — секунды каждый раз
  пересчитываются из `started_at` записи и текущего момента, а не хранятся в стейте
- Периоды День / Тиждень / Місяць считают реальные суммы из `work_entries`
- «Головна» показывает сегодняшний день из базы, привітання — ім'я з профілю
- `/time/manual` пишет закрытую запись через `createManualEntry`, выбор объекта —
  из реальных `sites`
- Лист швидких дій: «Почати роботу» і «Почати перерву» пишуть у базу, а не
  показують тост і нічого не роблять
- Моки часов удалены: `mock/timesheet.ts`, `mock/user.ts`, типы `DaySheet`,
  `TimeEntry`, `TimeEntryKind`, `TimelinePoint` из `lib/types.ts`
- Пункт «Дорога / Поза об'єктом» убран из списка быстрых действий: вёл в ту же
  форму, что «Додати час вручну», а «тип запису» ни на что не влиял — поле
  «Об'єкт» и так необов'язкове

**Откладываем:** офлайн, фото, экран команды.

**Две ошибки, найденные не на этапе 2, а здесь, при реальной проверке через REST**
(в обоих случаях — не гипотеза, воспроизведено на живой базе):

1. **Часовой пояс.** Server Actions исполняются на Vercel в UTC. Взять `new Date()`
   на сервере для «сейчас» значило бы писать смену студента из Фрайбурга со сдвигом
   на пояс дата-центра. Время старта/стопа/перерви считает браузер
   (`hhmmOf`/`dateKeyOf` в `modules/time`) и передаёт его действию явным параметром —
   сервер этому доверяет, а не считает сам.
2. **`break_pair` был слишком строгим.** Ограничение требовало оба края перерыва
   сразу — но «Почати перерву» физически может записать только `break_start`,
   `break_end` появится позже отдельным действием. Первая же попытка записать
   перерыв через REST падала с `23514`. Поправлено миграцией
   `0003_allow_open_break.sql`: запрещён только `break_end` без `break_start`,
   «перерва триває» — законное состояние. `stopCurrentShift` заодно закрывает
   повисший `break_start`, если зміну завершили, не завершивши перерву.

**Проверено через REST под живым токеном** (та же схема, что на этапе 2):
старт смены → повторный старт отклонён уникальным индексом → `break_start` без
`break_end` проходит → `break_end` без `break_start` падает по `break_pair` →
стоп с незакритою перервою закриває обидва поля одним запитом → `total_minutes`
сходится с ручным расчётом (345 − 45 = 300). `npm run test`, `npm run lint`,
`npm run build` чистые.

**Готово, когда:** смена, начатая на телефоне, видна на другом устройстве — да,
данные читаются из базы при каждой загрузке экрана; закрыл приложение и открыл —
таймер идёт, потому что секунды считаются от `started_at`, а не хранятся локально;
часы за неделю сходятся с суммой записей в базе — проверено вручную через REST,
а не на глаз.

## Этап 5. Офлайн

**Входит:**

**Откладываем:** разрешение конфликтов при одновременной правке. При одном авторе

принимает новую с фото; после включения сети она уходит **ровно один раз**, даже

## Что не входит ни в один этап

Названо явно, чтобы не расползлось само:

- Учёт материалов, смет, счетов и денег
- Расчёт зарплаты
- Подтверждение звітів шефом — решено, что его нет
- Чат и комментарии
- Геолокация и контроль присутствия
- Мультиязычность — только украинский
- Светлая тема
- Десктопная версия — на широком экране остаётся телефон по центру
- Магазины приложений
