# Развёртывание с нуля

Пошаговая инструкция: новая база Supabase + хостинг Vercel. Подходит и для первого запуска, и для переезда на другие аккаунты.

**Порядок важен:** база → ключи → хостинг → адреса возврата → первый шеф. Время: 30–45 минут.

## 1. База данных (Supabase)

1. Создайте проект на supabase.com. Регион выбирайте **рядом с хостингом** (у Vercel в `vercel.json` стоит `fra1` — Франкфурт; значит и база лучше во Франкфурте): каждая лишняя тысяча километров — это лишние ~30–100 мс на каждый запрос.
2. Откройте **SQL Editor** и выполните файлы из `supabase/migrations/` **строго по порядку номеров, от `0001` до `0021`**, каждый — отдельным запуском. Не пропускайте: приложение рассчитывает на все.
   - `0001` — таблицы, роли, права, представление часов;
   - `0002` — закрытая схема для служебных функций прав;
   - `0001` (бакет `entry-photos`), `0006`, `0014`, `0016` — хранилища фото (отчёты, объекты, аватары);
   - `0008` — отчёты, фото отчётов, категории работ;
   - `0015` — `is_other`, `other_text`; `0017` — «проблемное место»; `0018`–`0019` — дорога;
   - `0020` — подписки на push-напоминание (без неё приложение работает, но напоминаний нет);
   - `0021` — чеклисты, чаты 1 на 1 и настройки уведомлений (без неё главная и «Сповіщення» работают, но «Чеклисти» и «Чати» дают ошибку).
3. Выполните `supabase/bootstrap.sql` (после того как создадите шефа, п. 2 ниже) — он создаст фирму, профиль шефа и 14 стандартных категорий работ.

> На чистой базе миграция `0015` ничего не добавит в `work_categories` (фирм ещё нет), поэтому категории создаёт `bootstrap.sql`.

## 2. Первый шеф

1. Supabase → **Authentication → Users → Add user**: email и пароль шефа, отметьте «Auto Confirm User».
2. Откройте `supabase/bootstrap.sql`, подставьте название фирмы, email шефа и его имя, выполните в SQL Editor.
3. Дальше всё через приложение: шеф входит и заводит сотрудников в **Налаштування → Команда → Додати співробітника**.

`supabase/seed.sql` — демо-данные **только для локальной разработки** (пароль `kwork2026`). На боевой базе не запускать.

## 3. Ключи и переменные

В Supabase → **Project Settings → API** возьмите:

| Переменная | Откуда | Где используется |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL | браузер и сервер |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable (anon) key | браузер и сервер |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret (service role) key | **только сервер**: заведение сотрудников |

Секретный ключ никогда не кладётся в `NEXT_PUBLIC_*` и не коммитится.

**Интеграция Vercel ↔ Supabase.** Если подключить базу кнопкой в Vercel (Storage / Integrations), переменные создаются под другими именами: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` (или `SUPABASE_ANON_KEY`), `SUPABASE_SECRET_KEY` / `SUPABASE_SERVICE_ROLE_KEY`. Приложение понимает и их (`next.config.ts`, `src/lib/supabase/admin.ts`) — переименовывать не нужно.

**Рекомендуется** включить асимметричные ключи подписи (Authentication → JWT Signing Keys): тогда `proxy.ts` проверяет вход локально, без запроса в Supabase на каждый переход (`getClaims`). Без них приложение работает, но каждый переход на ~100 мс дольше.

## 4. Хостинг (Vercel)

1. Импортируйте репозиторий в Vercel, фреймворк определится как Next.js.
2. Добавьте три переменные из п. 3 в **Settings → Environment Variables** (Production и Preview).
3. Задеплойте. Каждый пуш в `main` выкладывается в Production автоматически.
4. Регион функций — `fra1` (`vercel.json`); менять вместе с регионом базы.

## 5. Адреса возврата для входа и сброса пароля

Без этого письмо «Забули пароль?» не приведёт на страницу нового пароля.

Supabase → **Authentication → URL Configuration**:

- **Site URL** — постоянный адрес сайта (`https://ваш-домен`).
- **Redirect URLs** — добавьте `https://ваш-домен/auth/callback` и для разработки `http://localhost:3000/auth/callback`.

**Шаблон письма «Reset password» нужно заменить** (Authentication → Emails), иначе ссылка работает только в том браузере, где запрашивали сброс (стандартный шаблон Supabase использует PKCE), а у установленного приложения (PWA) и браузера отдельные сессии: ссылка из письма открывается в браузере и «не находит» запрос — «посилання недійсне». Замените ссылку на вариант без привязки к браузеру:

```html
<p><a href="{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=recovery&next=/reset-password">Скинути пароль</a></p>
```

`/auth/callback` понимает эту ссылку и открывает форму нового пароля где угодно. После смены пароля человек возвращается в приложение и входит с новым паролем. Письма встроенной почтой Supabase идут с жёстким лимитом и часто попадают в спам — для боевой работы подключите свой SMTP: **Authentication → SMTP Settings**.

## 6. Проверка после запуска

- [ ] Вход шефа; на «Налаштування» видны «Команда» и «Компанія».
- [ ] Шеф создал работника; работник вошёл со своего телефона.
- [ ] Создан объект с фото; фото открывается (бакеты `site-photos`, `entry-photos`, `avatars` созданы миграциями).
- [ ] Добавлено время («Додати час»), оно видно на «Години».
- [ ] Создан отчёт с фото, с «проблемным местом» и с дорогой; блок «Дорога» виден на «Години».
- [ ] Экспорт CSV, Excel, PDF скачивается на выбранном языке.
- [ ] «Забули пароль?» присылает письмо и ведёт на форму нового пароля.
- [ ] Установка на домашний экран (Android: «Установить», iPhone: «Поделиться → На экран Домой»).
- [ ] В авиарежиме «Додати час» сохраняет запись («Не відправлено: 1»), при возврате сети она уходит.

## Напоминание о звіті (push, 18:00 по Брюсселю)

Каждый день в 18:00 по бельгийскому времени сотрудники, у которых включены уведомления (рабочим баннер предлагает включить сам, шеф включает в «Сповіщення» по желанию) и **нет отчёта за сегодня**, получают на телефон напоминание; нажатие открывает форму нового отчёта. Время и логика — `src/modules/reminders/`, отправка — `/api/cron/report-reminder`, запуск по расписанию — `pg_cron` в Supabase (Vercel Cron на бесплатном тарифе не даёт точного времени).

Один раз включить:
1. **Ключи.** В Vercel → Settings → Environment Variables (Production и Preview) добавьте четыре переменные — значения лежат в `.env.local` (там их создали) или создайте свои командой `npx web-push generate-vapid-keys` и `openssl rand -hex 32`:
   - `NEXT_PUBLIC_VAPID_PUBLIC_KEY` — публичный ключ;
   - `VAPID_PRIVATE_KEY` — секретный ключ (никуда не копировать);
   - `VAPID_SUBJECT` — адрес приложения, например `https://vk-group-chi.vercel.app`;
   - `CRON_SECRET` — длинная случайная строка.
   Потом **Redeploy** (публичный ключ вшивается в сборку).
2. **Таблица.** Выполните миграцию `0020_push_subscriptions.sql`.
3. **Расписание.** Откройте `supabase/cron-report-reminder.sql`, подставьте адрес приложения и тот же `CRON_SECRET`, выполните в SQL Editor.
4. **Телефоны.** Каждый рабочий: Налаштування → Сповіщення → включить «Нагадування про звіт» и разрешить уведомления. На iPhone только из установленного приложения (иконка на экране «Домой», iOS 16.4+).

Проверка без ожидания 18:00 (подставьте свой секрет): `curl -H "Authorization: Bearer <CRON_SECRET>" "<APP_URL>/api/cron/report-reminder?dry=1&force=1"` — вернёт `{"sent":N,...}`, сколько устройств получило бы напоминание, ничего не отправляя. Без `dry=1` напоминание уйдёт по-настоящему. Без `force=1` вне 18:00 по Брюсселю ответ — `"skipped":"not-18-brussels"`.

Как это ведёт себя: шефам не шлём; тем, кто уже отправил отчёт за сегодня, — тоже; одному устройству — не чаще раза в день; отозванные браузером подписки удаляются сами; текст — на языке интерфейса человека; переход на летнее/зимнее время ничего не требует.

## 7. Обновления

- **Код:** пуш в `main` → автодеплой Vercel.
- **База:** каждая новая миграция из `supabase/migrations/` выполняется в SQL Editor вручную, в порядке номеров. Миграции не правятся — меняются новой. Приложение терпимо к ещё не накатанным `0021` (главная и «Сповіщення» открываются, чеклистов и чатов нет), `0020` (просто нет напоминаний), `0017` (отчёт сохранится без «проблемного места») и `0018`/`0019` (дорога не запишется, будет предупреждение), но остальные нужны всегда.
- **Переезд на новые аккаунты:** повторить пп. 1–5; данные старой базы переносятся выгрузкой (CSV/Excel из приложения или `pg_dump`), фото — копированием бакетов Storage.
