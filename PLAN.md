## 0. Как работать с этим файлом

**Алгоритм на каждый запуск:**

1. Открой `PLAN.md`.
2. Найди **первый** шаг, у которого чекбокс `- [ ]` (не `- [x]`).
3. Прочитай раздел этого шага целиком, включая «Определение готовности».
4. Выполни шаг полностью. Не забегай вперёд, не делай задачи следующих шагов.
5. Проверь: `npm run build` и `npm run lint` проходят без ошибок.
6. Отметь чекбоксы шага как `- [x]`.
7. В конце шага в разделе «Журнал» допиши одну строку: `Шаг N — готово. <что создано, коротко>`.
8. **Остановись и отчитайся человеку.** Не начинай следующий шаг без запроса.

**Жёсткие правила фазы:**

- ❌ Никакого бэкенда. Ни API-роутов, ни базы, ни авторизации, ни fetch к внешним сервисам.
- ❌ Никаких новых npm-зависимостей сверх списка в разделе 2. Нужна ещё одна — сначала спроси человека.
- ❌ Не выдумывай экраны, которых нет в плане. Скоуп фазы — 4 вкладки + флоу кнопки «+». Остальное (детальные страницы объекта/отчёта, профиль, уведомления, авторизация) — следующая фаза, пока не трогаем.
- ✅ Все данные — статические моки из `src/lib/mock/`. Состояние живёт в React-стейте, при перезагрузке сбрасывается. Это нормально.
- ✅ Все тексты интерфейса — украинские, **только** через словарь `src/lib/i18n/uk.ts`. Ни одной строки текста хардкодом в JSX.
- ✅ Mobile-only. Проектируем под ширину 390px. На десктопе — телефон по центру экрана.
- ✅ Тёмная тема — единственная. Светлой темы нет, переключателя нет.

## 1. Что за продукт

Мобильное веб-приложение (PWA) для сотрудников строительной компании **K group**. Работник в поле:

- отмечает начало / паузу / завершение рабочего дня, видит таймер;
- смотрит список своих объектов (стройплощадок) и их статус;
- смотрит и создаёт отчёты по проделанной работе с фото;
- видит статистику отработанного времени за день / неделю / месяц.

Основная механика — **учёт рабочего времени**, всё остальное вокруг неё.

Тон интерфейса: строгий, крупный, тёмный, с одним ярким жёлтым акцентом. Всё нажимаемое — минимум 44×44px, работник в перчатках на стройке. Никаких мелких шрифтов и тонких линий.

|---|---|

**Важно про Tailwind:** проверь установленную версию. Если Tailwind v4 — конфиг живёт в CSS через `@theme`, файла `tailwind.config.ts` нет и создавать его не надо. Если v3 — конфиг в `tailwind.config.ts`. Не смешивай подходы.

## 3. Дизайн-система

### 3.1 Цвета

Тёмная тема, единственная. Токены задаём один раз в `globals.css`, дальше пользуемся только семантическими именами.

| Токен | HEX | Где применяется |
|---|---|---|
| `--bg` | `#0A0A0C` | фон всего приложения |
| `--surface` | `#131418` | карточки, поля ввода, таб-бар |
| `--surface-2` | `#1B1D22` | вложенные блоки, неактивные сегменты, скелетоны |
| `--border` | `#25272C` | границы карточек и полей (1px) |
| `--brand` | `#FFC93C` | главный жёлтый: FAB, основные кнопки, активная вкладка, логотип |
| `--brand-ink` | `#0A0A0C` | текст поверх жёлтого (всегда тёмный!) |
| `--text` | `#FFFFFF` | заголовки, основной текст |
| `--text-muted` | `#8E9099` | подписи, адреса, метаданные |
| `--text-dim` | `#5C5E66` | неактивные иконки таб-бара, вспомогательное |
| `--success` | `#4ADE80` | статус «В РОБОТІ», «ЗАВЕРШЕНИЙ» |
| `--warning` | `#FBBF24` | статус «НА ПАУЗІ» |
| `--danger` | `#F87171` | ошибки, деструктивные действия |

Фоны бейджей — цвет статуса с прозрачностью 12–14%, текст — сам цвет статуса на полной непрозрачности.

### 3.2 Типографика

Manrope. Размеры (mobile):

| Роль | Размер / начертание | Пример |
|---|---|---|
| Заголовок экрана | 30px / 800 | «Об'єкти», «Звіти», «Години» |
| Таймер | 56px / 800, `tabular-nums`, tracking -0.02em | `05:42:18` |
| Крупная метрика | 34px / 800 | «5 год 42 хв» |
| Заголовок секции | 20px / 700 | «Мої об'єкти» |
| Название карточки | 17px / 700 | «Villa Project» |
| Основной текст | 15px / 500 | |
| Подпись / мета | 13px / 500, цвет `--text-muted` | «Freiburg, Schlossgasse 24» |
| Бейдж | 11px / 700, uppercase, tracking 0.06em | «В РОБОТІ» |
| Подпись таб-бара | 11px / 600 | «Головна» |

### 3.3 Формы и отступы

- Радиусы: карточка `16px`, кнопка `14px`, бейдж `8px`, миниатюра объекта `12px`, FAB — круг.
- Горизонтальные поля экрана: `16px`.
- Вертикальный зазор между карточками в списке: `12px`.
- Внутренний паддинг карточки: `16px`.
- Высота основной кнопки: `56px`. Высота поля ввода: `52px`.
- Тени почти не используем — разделяем блоки цветом поверхности и границей `1px --border`.
- Безопасные зоны: `env(safe-area-inset-bottom)` под таб-баром, `env(safe-area-inset-top)` в шапке.

### 3.4 Состояния статусов

Единый справочник, используется на всех экранах:

| Ключ | Текст (uk) | Цвет |
|---|---|---|
| `in_progress` | В РОБОТІ | success |
| `not_started` | НЕ РОЗПОЧАТО | muted (текст `--text-muted`, фон `--surface-2`) |
| `completed` | ЗАВЕРШЕНИЙ | success |
| `paused` | НА ПАУЗІ | warning |

## 7. Что НЕ входит в эту фазу

Не делай, даже если кажется логичным. Обсудим отдельно:

- детальная страница объекта и детальная страница отчёта (переходы по стрелкам «›» пока никуда не ведут);
- создание и редактирование отчёта;
- профиль пользователя и экран уведомлений;
- авторизация, splash, онбординг;
- реальные фотографии, загрузка файлов, геолокация;
- бэкенд, база данных, сохранение состояния;
- немецкая и английская локализация (структура под них уже заложена).
